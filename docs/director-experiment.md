# 同模型 T8 分鏡實驗

目標：先驗證在使用者提供大致主軸時，導演能否自主做出有用的表演、運鏡、
細節插鏡與剪輯選擇。可用原有通用模型對照測參數規模；新增實驗則單獨測 T8
方法的增量。這兩種問題分開評估。

## 對照條件

| 條件 | Off | On |
| --- | --- | --- |
| 模型 | 同一個通用 Qwen3.5，預設 27B | 相同 model ID 與本次固定 revision |
| 指令 | 精簡、自主創作的導演 system | 同一 system 加固定 T8 storyboard 方法 |
| 任務與圖片 | 同一份主軸、聲部時間、來源圖 | 相同 payload 與圖片順序 |
| 輸出 | 六區塊 Ref2VA 草稿 | 相同 |
| 取樣 | NF4、thinking=false、共同 seed、.7/.8/20 | 相同 |

這不是精簡指令與舊 Banana 堆疊的 A/B，也不是「T8 全插件 vs Banana」。
它只回答同一基線加上 T8 storyboard modifier 是否有幫助。T8 原文包含其自身
限制與權限邊界；沒有再把舊版 FREE／攝影／表演規章疊到它前面。

上游文件：[方法與證據界線](https://github.com/T8mars/comfyui-minimax-h3-prompt-enhancer-T8/blob/25a8caafac8d4d77f5d0e11b6c01f1491903d5f5/docs/storyboard-director.md)。
上游明確將此功能列為實驗，沒有已證明的真實 GGUF／成片 A/B 正收益。
它借鑑的原 v20 私有文件不在本倉庫，也沒有重建或發布該原文。

## 執行

1. 使用實驗分支的 Colab，或先準備 T8 來源再啟動 app。
2. 先用預設案例；有圖片則在主軸指定各 Picture 的用途，避免以圖號猜身分。
3. 按上方「同一位導演，拍兩版比較」。只在按鈕按下後下載／載入模型。
4. 下載 JSON，再換 seed、反轉順序及換題材。先用少量案例找問題；小樣本不能
   宣稱普遍優勢。不要只保留好看的稿。
5. 輸出上限命中時保留原始稿，標記截斷，增加預算後另做一輪。

介面固定本段 15 秒；程式函式接受任務 seconds。要比較其他時長，可從 Python
呼叫 `compare_directors`，並同步調整 local_vocal_cues。這是實驗預設長度，
不是 H3 或 T8 的時長上限。聲部分配只檢查數值範圍，不聲稱已聽懂聲線。

## 人工驗收

- 故事有沒有前進，角色／道具／操作與結果是否承接。
- 每個鏡頭帶來什麼新資訊或觀看關係；鏡數多不自動加分。
- 情緒是否外化為可見表演，而非一直引用表情表；是否符合使用者指定的情緒。
- 攝影是否真的改變構圖、前後景和觀眾注意力，而非一直推近。
- 聲部分配與角色身分是否正確；原曲權限、場景隔離與指定結果是否保留。
- 運鏡、切點與動作是否形成可執行草稿。

不要用關鍵字數、文章長度、固定鏡數或另一顆模型的主觀評分代替判斷。
出現失敗時，引用具體 Shot 與原始輸入，區分來源矛盾、模型不服從、預算截斷。

## H3 生成界線

原始輸出是供審閱的 Ref2VA 草稿，本工具沒有連接 H3、正式 MV 或 ComfyUI。
下游完整官方指南／節點驗證尚未整合，六區塊交稿不等於 H3 接受或能照做。
先選出可比的兩份稿，再用同素材、音軌、H3 設定及 render seed 做生成比較，
才能討論真實表演、對嘴、運鏡或 Seedance 等級的體驗。

## 驗證紀錄

離線測試使用模擬 backend 驗證同模型／同輸入、Off／On 差異、反轉順序、
部分失敗保存，以及來源雜湊錯誤時不呼叫模型。實際 T8 固定檔案已下載及解析。
本機無 CUDA／模型權重；沒有做真實 Qwen 推論或影片生成，不發布虛構對照結果。
